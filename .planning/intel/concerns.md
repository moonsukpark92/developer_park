## 0. 요약 (TL;DR)

본 프로젝트는 코드가 아닌 **콘텐츠 자산**이 핵심이다. 따라서 가장 큰 위험은 빌드 실패가 아니라 **(1) 민감정보 누출, (2) 작가 페르소나 훼손, (3) 외부 서비스 종속, (4) 콘텐츠 양 증가에 따른 일관성 붕괴**다. 우선순위는 P0(차단성) → P3(장기 모니터링) 순으로 분류한다.

| 우선순위 | 영역 | 핵심 위험 |
|----------|------|-----------|
| **P0** | 민감정보 정책 | 직원 실명/금융/내부 URL 누출 → 사내 신뢰 붕괴, 법적 분쟁 가능 |
| **P0** | 회사 명칭 정책 | `(주)데코페이브` 일관성 — 공식 표기 오류는 회사 이미지 직결 |
| **P1** | 작가 문체 보존 | 박문석 페르소나(구어체, 감정선) 훼손 시 시리즈 정체성 상실 |
| **P1** | 콘텐츠 출처 무결성 | `decohub_agent` 실제 워크폴더 데이터 vs. 픽션 — 사실 왜곡 위험 |
| **P2** | 외부 서비스 의존 | Buttondown/Giscus/GoatCounter — 서비스 중단 시 구독자/댓글 데이터 소실 |
| **P2** | 운영 채널 단일화 | GitHub Pages 단일 배포 — 저장소 사고 시 백업 시나리오 부재 |
| **P3** | 콘텐츠 양 증가 | S3 13+편 도달, 네비/인덱스/마스킹 일괄 갱신 비용 누적 |
| **P3** | 시리즈 진화 일관성 | S1(밝음) → S2(다크) → S3(딥다크) 톤 차이 — 첫 독자 혼동 가능 |

1. **신규 EP 추가 시 기존 EP 네비 누락:** 모든 형제 EP의 하단 네비에 새 EP 링크 추가 필요. 누락 시 사용자가 새 글 도달 불가.
2. **시즌 인덱스(`s3/index.html`) 갱신 누락:** EP 칩 누락 → 시즌 페이지에서 새 EP 미노출
3. **메인 인덱스(`index.html:330`) 갱신 누락:** EP 칩, 통계(35 Episodes) 갱신 누락
4. **사용 안 되는 파일 누적:** `_archive/`, `_inbox/` 누적 → 디스크 압박 + 검색 노이즈
5. **마스킹 일괄 회귀:** 1건 EP 추가 시 다른 EP 우발 수정 → 마스킹 풀림 가능
