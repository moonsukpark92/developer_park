Chapter 01

3개월 바이브 코딩
— 지금 어디까지 왔나

VS Code에 Claude Code, 각종 익스텐션 깔고 바이브 코딩을 시작한 지 3개월이 다 돼간다. 처음엔 재고 관리 하나였다. 데코페이브 스탁. 그게 지금은 재무·회계 빼고 회사 전체 기능을 탑재한 수준까지 올라왔다.

그런데 솔직히 말하면 — 지금 한계에 와 있다.
너무 방대하고 비대해진 덩어리가 됐다. 주 모듈이 너무 커져서 로딩 시간이 길어지고, DB 구조를 처음부터 완벽하게 설계 안 한 탓에 연결하는 과정에서 문제가 생기고. 이걸 어떻게 할까를 일주일째 Claude와 고민 중이다.

그 고민 속에서 자연스럽게 다시 공부가 시작됐다.
YouTube에 좋은 기술과 플러그인은 넘쳐나는데, 다 듣고 이해하고 만들기엔 시간이 없다. 그래서 지금 쓰는 방법들이 생겼다.

"전체적인 틀은 바이브 코딩으로 빠르게 잡힌다.
하지만 실제 써보면 — 디테일이 상당히 복잡하다."

Chapter 02

요즘 공부하는 방법 ①
Gemini × YouTube → Claude Code

YouTube에 최신 기술 영상이 쏟아진다.
그걸 다 보고 내 것으로 만든다는 건 불가능하다. 너무 많다.
그래서 나온 방법이 이거다.

01

Gemini에게 YouTube 동영상 분석 요청

링크를 넣으면 Gemini가 영상 전체를 분석한다. 핵심 기술과 구조 추출. 직접 볼 필요 없다.

02

Perplexity로 보강 → CLAUDE.md 파일로 정리

분석 결과를 다른 AI로 한 번 더 보강한다. Claude Code가 컨텍스트로 읽을 수 있는 .md 형식으로 변환.

03

Claude Code에게 "우리 상황에 적용 가능한지 검토 → 적용 계획서 작성"

VS Code에서 경로 인식시켜 Claude Code가 판단하게 한다. 쓸 수 있는 기술만 걸러내서 구현.

04

계획서를 반드시 직접 읽어본다

안 된다고 하는 AI는 잘 없다. 위험 부담이 있어도 "된다"고 한다. 최종 판단은 반드시 내가 한다.

Gemini가 먼저 소화하고, Claude Code가 우리 코드로 만든다.

Chapter 03

요즘 공부하는 방법 ②
깃허브 클론 → 분석 → 접목

깃허브에 내가 생각하는 것과 비슷한 프로젝트들이 꽤 있다. 그 링크를 가져와서 Claude Code에게 스터디시키고, 클론하고, 소스코드 중에 우리가 접목할 수 있는 게 뭔지 분석하게 한다. 그걸 다시 프로그램에 업데이트하고 테스트하고. 기술 확장과 안정화를 동시에 진행하는 방식이다.

# 깃허브 클론 → 분석 루프
$ git clone https://github.com/similar-project/repo
→ Claude Code: 소스코드 구조 분석 중...
→ 우리 프로젝트와 접목 가능 모듈 식별: 3개
$ 접목 계획서 작성 → 업데이트 → 테스트
✓ 기술 확장 완료 — 다음 섹션으로

Chapter 04

AI끼리 서로 비판하게 만든다
— 정제된 계획서가 나올 때까지

Cursor 깔고, Codex 깔고, Claude에게도 시켜봤다. 각자 자기가 잘한다고 한다.
그래서 지금 쓰는 방법 — Codex에게 먼저 소스코드 리뷰·디버깅·계획서 초안을 만들게 한다. 그 계획서를 Claude Code에게 준다. Claude Code가 검토하면서 "이건 쓸데없는 작업이다"라고 비판한다. 비판한 .md 파일을 다시 Cursor에 넣고 한 번 더 돌린다.

몇 번 왔다 갔다 하면 약간 정제된 계획서가 나온다. 그 계획서를 하나하나 찾아가면서 구현하는 것이 지금 방식이다. 각 메뉴 섹션별로 나눠서 코드 리뷰, 디버깅을 먼저 하고 있다. 한 번에 다 바꾸다가 잘못되면 엉키기 때문에 — 섹션마다 최대치로 정리하고 넘어간다.

Chapter 05

밤새 돌아가게 하는 방법
— Playwright 자동 테스트

리뷰·디버깅 프롬프트를 줄 때 한 가지를 꼭 붙인다 — "시니어 개발자가 해라." 그리고 마지막에 이걸 추가한다.

"무조건 베타 테스트를 실행해서 실제로 네가 가동해봐라."

그러면 MCP에 깔린 Playwright가 실제로 브라우저를 구동해서 테스트한다. 에러가 나면 디버깅하고, 다시 원점에서 돌아가서 다시 시작한다. 그러면 밤새 돌아간다. 아침에 일어나면 에러가 줄어있다. 프로그램이 더 단단해져 있다.

# Claude Code + Playwright MCP 자동 테스트 루프
→ 시니어 개발자 모드 — 코드 리뷰 시작
$ playwright test --headed
✗ Error: Button click handler undefined — line 342
→ 원점 복귀, 재디버깅...
$ playwright test --headed
✓ All tests passed — 에러 0건, 다음 섹션으로
# 이게 밤새 반복된다

Chapter 06

계획서와 개발 일지
— 이게 없으면 길을 잃는다

깃허브에 올리고, 커밋도 계속 한다. 하지만 어느 순간 어디서 잘못됐는지 모르는 채로 완전히 다른 세계의 소스코드가 될 때가 있다. 그래서 지금 필수로 하는 것이 두 가지다.

A

개발 완료 후 → Claude Code가 개발 일지 자동 작성

오늘 뭘 했는지 AI가 일지로 남긴다. 여러 세션에서 작업해도 일지가 있으면 추적된다.

B

개발 일지 → 기존 계획서 업데이트

일지를 근간으로 계획서를 보강한다. 문제가 생겨도 계획서와 일지 덕분에 커버할 수 있다.

몰두해서 작업하다 보면 컨텍스트 윈도우를 벗어나 세션이 죽는다.
50% 이상 넘어가면 — 새로운 세션에서 시작하거나 전용 플러그인으로 분리한다.
